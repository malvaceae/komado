# 開発ガイド

## 現状

macOSの共通コードをSwift Packageとして、Androidの共通コードをKotlinのJVMモジュールとして実装しています。macOSのメニューバーアプリは、ログイン時のアプリ起動の設定、待ち受けの開始・停止、ペアリング情報の発行、登録端末の表示と削除を行い、共有時はメニューとウインドウに共有中の対象と停止操作を表示します。共有停止時は現在の接続を切断しますが、待ち受けは続けます。Androidアプリは接続先の保存、QRコードまたは手動でのペアリング、認証済み接続とディスプレイ・ウインドウの表示・選択に対応し、表示をピンチやボタンで拡大・縮小できます。拡大中はタッチの移動や矢印キーで表示位置を移動できます。操作欄が画面に収まりきらない場合は、映像領域を確保し、操作欄をスクロールできます。Mac側では映像の最大解像度を標準（1280×720）と低解像度（854×480）から選べ、次回の画面共有から適用します。解像度は縦横比を保ち、小さい画面やウインドウを拡大しません。選択した画面とウインドウの操作を初期実装しています。音声転送は未実装です。配布手順はまだ整備されていません。技術検証用のコードは[検証手順](../experiments/README.md)を参照してください。

## 開発の進め方

1. [開発計画書](development-plan.md)のPhase 0で、両側のWebRTCライブラリ、画面取得、同一LAN・Tailscale経由の接続、入力、互換性を検証する。
2. 検証条件と結果を記録し、ライブラリ、最低対応OS、ABI、実現上の制約を決める。主要な選定とトレードオフは[ADR](decisions/README.md)に残す。
3. Phase 0の完了条件を満たしたうえで、基本リモートデスクトップ、ウインドウモード、実用性向上、配布へ進む。音声など基本操作と独立した課題は記録したうえで後続フェーズに持ち越せる。
4. プロトコルを定義した際は、両側の実装、[スキーマ・フィクスチャ](../protocol/README.md)、ドキュメントを合わせて更新する。
5. ビルドと自動テスト、エミュレーター、実機を区別して結果を記録し、未検証の環境を保証しない。

フェーズごとの作業と完了条件は[開発計画書 §12](development-plan.md#12-開発計画)を参照してください。

## 共通コードのテスト

XcodeのCommand Line Toolsが選択されている場合も含め、Xcodeを指定して実行できます。

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path macos
```

Macアプリの開発用ビルドは次のコマンドで作成できます。`.build/komado.app`はローカル確認用のアドホック署名であり、配布用の署名や公証は行いません。

macOSのローカルネットワーク権限は操作の種類により必要です。AppleはTCPの受信待ち受けには不要、ローカルネットワーク宛ての送信には必要と説明しています。配布時の署名と権限の扱いは[Appleの案内](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)に従って検証します。

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./macos/build-app.sh
open macos/.build/komado.app
```

Apple SiliconとIntelの両方を含む開発用アプリは、`./macos/build-app.sh --universal`でビルドできます。生成したバイナリのアーキテクチャは`lipo -archs macos/.build/komado.app/Contents/MacOS/KomadoHost`で確認できます。対応OSや各実機での動作は、ビルドとは別に確認が必要です。

Android側はJDKを用いて実行します。

```sh
./android/gradlew -p android :core:test
ANDROID_SERIAL=emulator-5554 ./android/gradlew -p android :security:connectedDebugAndroidTest :security:lintDebug
ANDROID_SERIAL=emulator-5554 ./android/gradlew -p android :app:connectedDebugAndroidTest
./android/gradlew -p android :app:assembleDebug :app:lintDebug
```

`connectedDebugAndroidTest`は起動済みのエミュレーターが必要です。シリアルは対象の環境に合わせて指定します。

Android 17以降のエミュレーターでネットワークを使うアプリの自動テストを実行する場合は、テスト前にデバッグアプリをインストールし、エミュレーターのローカルネットワーク権限を付与できます。

```sh
ANDROID_SERIAL=emulator-5554 ./android/gradlew -p android :app:installDebug
adb -s emulator-5554 shell pm grant me.mallows.komado android.permission.ACCESS_LOCAL_NETWORK
```

通常のアプリ操作では、Android 17以降で接続時に権限を要求します。拒否した場合もVPN接続を試せますが、VPN経由の動作は未検証です。

[GitHub ActionsのCI](../.github/workflows/ci.yml)では、macOSのビルドと非対話のテスト、AndroidのJVMテスト・lint・デバッグビルドを実行します。macOSの画面収録、Accessibilityによる入力、スリープ抑制、Keychainやネットワーク環境に依存するテスト、Androidのエミュレーター・実機テストはCIに含めていません。Xcode 27のランナーはプレビュー版です。CIの実行結果はGitHub上で確認してください。

手動ペアリングでは、Macで確認情報を作成して待ち受けを開始し、表示された接続先アドレス・ポート、フィンガープリント、発行したペアリングコードをAndroidに入力します。VPN経由の場合はMacのVPNアドレスを指定して待ち受けを開始します。各アドレスに別のポートが割り当てられ、ネットワーク構成が変わるとポートが変わる場合があります。IPv6のリンクローカルアドレスは、Android側のインターフェース名をゾーンとして指定する必要がある場合があります。別端末でのLAN・VPN接続とIPv6の実動作はまだ検証していません。

QRペアリングでは、Macで接続先を選んでペアリング情報を発行し、Androidの「QRコードでMacを追加」から読み取ります。表示元のMacを確認し、必要に応じてAndroid側で接続先を編集してからペアリングします。IPv6のリンクローカルアドレスではゾーン名の変更が必要になる場合があります。カメラが使えない場合は手動入力できます。

接続先一覧の「最終認証」は、ペアリングまたは再認証に成功した端末の時計による時刻をAndroidに保存して表示します。画面転送の開始成功や現在のオンライン状態を意味するものではありません。接続先を削除すると履歴も削除します。

「接続を確認」の実行後は、その確認時刻と成功・失敗を接続先一覧にも表示します。結果はメモリ内の情報で、画面の再作成・終了時に消えます。現在のオンライン状態を保証するものではありません。接続先のアドレスやポートを変更すると、変更前の結果は表示しません。

画面表示の接続中は、Macの認証、対象一覧の取得と選択、映像の接続をそれぞれ表示します。

ペアリング済みの接続先から「画面を見る」を選ぶと従来どおりメイン画面を表示します。「画面を選択」では認証後に有効な画面の一覧を取得し、番号とピクセルサイズから選んで表示します。画面をキャンセルすると接続を終了します。旧バージョンのMacアプリでは画面一覧を取得できないため、「画面を見る」を使ってください。Android側では画面名を表示せず、同じサイズの画面は番号だけでは区別しにくい制約があります。「画面を選んで操作」ではMacの操作許可とAccessibility権限を必要とします。複数画面での切り替えや操作は未検証です。

操作画面の「トラックパッドに切替」は、指の移動でカーソルを動かし、タップ・長押し・ドラッグと二本指スクロールをカーソル位置へ送ります。切り替え時のカーソル位置は表示中央です。映像上の円は操作位置を示し、ピンチや拡大ボタンも使えます。Macがポインター移動に対応しない場合や回転情報がある映像では切り替えられません。「感度」からカーソル速度とスクロール感度を50〜200%で個別に設定でき、設定は端末に保存されます。実機での操作感や表示は未検証です。

手動クリップボード共有は、Macの操作許可に加えて「クリップボード共有を許可」を有効にし、Androidの操作画面で方向を選びます。テキストのみ最大16,384 UTF-8バイトに対応し、Androidから送る前にMacの許可を確認します。共有許可は操作終了時に解除します。自動同期はさらにMac側とAndroid側でそれぞれ有効にします。有効化時の既存内容は送らず、Androidの画面がフォーカスされている間の変更を同期します。機密指定された内容などは自動送信しませんが、機密指定のない情報が転送される可能性があります。Android実機と一般のアプリでの動作は未検証です。

Androidの`VideoViewport`は映像をアスペクト比を維持して表示した際の余白、倍率、移動を考慮し、表示範囲内のタッチを正規化します。macOSの`CaptureGeometry`はCore Graphicsのグローバル座標（ポイント単位）のキャプチャ領域と正規化座標から入力先の座標を求め、無効な座標や現在と異なるキャプチャリビジョンを拒否します。映像のコンテンツ領域を使った座標変換と対象のフォーカス確認、入力送信を初期実装しています。実際のOSへの配送と表示との一致は未検証です。端末認証と認証後の画面表示はエミュレーターで確認済みですが、Android実機では未検証です。

「ウインドウを選択」では認証後にアプリ名とタイトルの一覧を取得し、選んだウインドウを表示します。一覧はアプリ名またはタイトルの一部で絞り込めます。各名称は最大96 UTF-8バイトに短縮されます。非表示のウインドウも一覧に含まれ得ますが、選択しても取得できない場合があります。選択前にタイトルやサイズが変わった場合は接続を終了するため、一覧を開き直してください。単一ウインドウの取得では別ウインドウのメニューやダイアログが映らない場合があります。「ウインドウを操作」はMac側で操作許可とAccessibility権限を必要とし、画面上で見えている部分だけを操作します。入力時に位置や重なりを確認し、文字入力にはフォーカスが必要です。位置やサイズを変更した場合は接続し直してください。実際の操作配送は未検証です。

## 環境と手順の整備予定

macOSはXcode / Swift / Swift Package Manager、AndroidはAndroid Studio / Kotlin / Gradle Kotlin DSLを候補とします。最新安定版の利用を基本とし、実際の対応状況を確認してバージョンを固定します。Tailscale経由で接続する場合は各端末にTailscaleが必要です。

プロジェクト作成後、以下を実際に確認して追記します。

- 必要なツールのバージョンとインストール手順。
- ローカルでのビルド、フォーマット、静的解析、自動テスト、実機実行のコマンド。
- macOS権限の設定、Tailscaleの設定、接続・ペアリングの手順。
- CIとリリース成果物の作成、署名、公証に必要な設定。秘密情報や署名鍵はリポジトリに含めない。

ディレクトリ構成とCI/CDは[開発計画書 §11](development-plan.md#11-リポジトリ構成)および[§14](development-plan.md#14-cicd配布)の初期案を参照してください。配布やリリース用ワークフローはまだ存在しません。

Androidの画面表示中は「接続情報」で受信映像のサイズ、フレームレート、通信の往復時間を確認できます。値が取得できない場合はその旨を表示します。通信の往復時間は、操作してから画面に反映されるまでの時間ではありません。統計は表示時に取得し、接続先アドレスや内容を表示・保存しません。

macOSの「ログイン時にkomadoを起動」はOSのログイン項目に登録します。システム設定での許可が必要な場合は案内します。アプリを起動する設定であり、接続待ち受けは起動後に手動で開始します。
