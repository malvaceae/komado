# アーキテクチャ

この文書は[開発計画書](development-plan.md)の構成を開発用に整理したものです。実装と検証の範囲は[互換性](compatibility.md)を参照してください。

## 構成

```text
Android client                              macOS host
登録・接続 / IME / touch                   SwiftUI / AppKit
         │                                           │
         ├──── フレーム付きTLS: signaling ──────────┤
         └──── WebRTC: video, audio, data ───────────┘
                     到達可能なネットワーク
                                            ScreenCaptureKit / VideoToolbox
                                            Accessibility / Core Graphics
```

端末間で到達できるネットワークを利用します。VPNを使う場合は各端末の既存クライアントを利用します。Macの待ち受け範囲は[ネットワーク接続の決定](decisions/0001-network-access.md)を参照してください。macOS側のシグナリングサーバー、Android側の登録・認証、ディスプレイ・アプリ・ウインドウの表示と操作、音声転送を初期実装しています。シグナリングはTLS上の長さ付きフレームです。komado専用のクラウド、VPN、STUN、TURNサーバーは原則設けません。

Macは画面取得中、`ProcessInfo`のアクティビティでアイドルによるシステムスリープを抑制し、画面転送の終了時に解除します。待ち受け中も抑制する設定は初期状態ではオフで、有効にすると待ち受けの終了または設定の解除時に抑制を解除します。ディスプレイのスリープや明示的なスリープは抑制せず、MacBookの蓋を閉じた場合の継続動作は保証しません。

1ホストにつき同時に操作できるクライアントは1台です。Androidには複数ホストを登録できます。

## 責務

- **macOS**：画面・音声の取得、操作対象の列挙とウインドウ制御、入力イベントの反映、認証とセッション管理。
- **Android**：ホスト登録、表示対象の選択、映像表示、タッチ・キーボード・IME入力、接続状態の表示。
- **共通**：メッセージ仕様、エラー、互換性テストデータ。

候補技術の一覧は[開発計画書 §5](development-plan.md#5-技術スタック)を参照してください。認証済みシグナリングからWebRTCでメインディスプレイを送信する処理を組み込み、エミュレーターで確認しました。別端末やVPNでの検証は残っています。

## 操作対象と座標

ディスプレイ全体、アプリとウインドウ単位のキャプチャを初期実装しています。アプリ単位では選択したアプリのウインドウがある一つのディスプレイを取得します。操作対象と同一アプリへの入力を照合します。実入力はテスト用アプリで確認済みで、一般アプリでは未検証です。テストアプリのコンテキストメニューとモーダルダイアログはMacの映像での表示とAndroidエミュレーターからの操作を確認しています。メニューバーはアプリ単位では映らず、画面全体への切り替えで扱います。バックグラウンドのウインドウをMac本体の操作に影響なく独立して操作することは初期要件ではありません。

入力座標はキャプチャ対象の映像領域を基準に正規化し、表示倍率と余白を考慮して変換します。現在、回転情報のある映像の操作は拒否し、画面環境が変わった場合は接続を終了します。リビジョンが一致しない入力は破棄し、キー入力時はフォーカスされたウインドウが対象ディスプレイにあることを確認します。ウインドウ単位の操作では位置・サイズや重なりを照合し、キーボード入力時はフォーカスを確認します。

## 技術検証の優先事項

- LANやVPNでICE接続できるか。認証済みシグナリングとWebRTCの相手を安全に結び付けられるか。
- ScreenCaptureKitのフレームをWebRTCへ渡せるか、H.264のハードウェア処理が実機で利用できるか。
- ウインドウの列挙・取得・フォーカス・リサイズ、隠れた／最小化されたウインドウやメニューの挙動。
- Android IMEの確定文字列と物理キーイベントを区別し、日本語や特殊キーを対象アプリに反映できるか。
- 音声の対象範囲、音質、遅延と実機での動作。

[テスト計画](testing.md)と[互換性](compatibility.md)に結果を記録し、主要な選定は[ADR](decisions/README.md)で決定します。
