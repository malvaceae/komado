# 互換性

以下は対応候補です。ビルドやエミュレーターで確認したことと、実機での動作は区別します。実機検証を含む完了条件は[テスト計画](testing.md)を参照してください。

| 対象 | 候補・確認状況 |
|---|---|
| macOS | macOS 13以降。最低OSを13としたビルドは成功したが、macOS 13での実行は未検証 |
| Mac CPU | Apple Silicon・Intel。両方を含む開発用アプリとWebRTCフレームワークをビルド済み。Intel実機は未検証 |
| Android | Android 8 / API 26以降。API 26・36・37のarm64エミュレーターでテスト済み。実機は未検証 |
| Android ABI | APKにarm64-v8a・armeabi-v7a・x86・x86_64のWebRTCライブラリを同梱。arm64とx86_64のエミュレーター以外は未検証 |
| 接続 | 到達可能なLAN・VPNなど。別端末間のLAN接続、VPNとモバイル回線は未検証 |
| 配布 | ローカル確認用Macアプリと未署名Android APKをビルド済み。配布用署名・公証・実機への配布は未検証 |

## 主な検証結果

2026-11-28時点。特記しない限り、MacはmacOS 26.7.3・Apple Silicon・Xcode 27.2、Androidは同じMac上のエミュレーターです。WebRTCはmacOS側158.0.0、Android側1.3.10を使用しました。自動テストは[開発ガイド](development.md)の手順で実行できます。Android API 26・37でアプリと認証・通信の端末上テストを実施しました。両OS間の一時テストは検証専用の保存領域を使い、テストコードは残していません。

| 対象 | 確認した範囲 | 未検証・制約 |
|---|---|---|
| ペアリング・認証 | AndroidのAPI 26・36・37エミュレーターとMacを接続。手動または仮想カメラのQRによる登録、再認証、不一致の証明書の拒否を確認。API 37ではAndroidの登録画面から手動ペアリングも確認 | 実カメラ、別端末、実機の鍵保護とVPNは未検証 |
| 映像 | API 37のAndroidアプリ画面からテスト環境のMacホストに接続。画面の回転・接続終了と、再認証後の表示を5回確認。EGL共有を修正後、変化するテストウインドウの映像を通常・全画面で表示。操作中にテストウインドウ同士と画面・ウインドウ間を切り替え、操作許可の維持と切断時の解除を確認。API 26・37では映像停止後の通信再開と描画の再初期化も個別に確認。API 37で横長映像の左右端の表示と入力座標の対応を確認。全画面の開閉・回転はAPI 26・37で確認。画面一覧の変化は擬似データで検証 | 取得開始順序の修正後に一度発生した映像開始失敗は原因未特定。静止映像での全画面切り替え、メイン画面の画面操作、一般アプリ、最小化、複数画面、Android実機は未検証 |
| 文字・キー入力 | 認証済み接続で、API 37のテスト用IMEの未確定文字はMacに届かず、確定した日本語・絵文字がテスト用Macアプリの文字欄に届くことを確認。Androidアプリ上での英数字キー入力も確認。API 37に外付けキーボード相当のイベントを注入し、Macのテストアプリで文字と左矢印を受信。長文の分割、未確認時の案内、古いIME接続の拒否も個別テスト | 実際の日本語IMEによる変換、一般アプリ、他のIME、物理キーボードと実機は未検証 |
| ポインター・ウインドウ | 一覧取得後のタイトル・サイズ変更をMacで確認。認証済み接続でテスト用Macアプリの選択ウインドウを前面化し、Androidアプリ画面のタップと文字入力を配送。API 37では別プロセスのテストアプリの2ウインドウを表示し、対象への入力と別アプリへの誤入力の拒否を確認。自動リサイズ、Androidの回転・全画面切り替え、解除・切断時の復元も確認。API 26では自動リサイズ後のタップ相当の入力をテスト用ウインドウに配送。最小サイズの尊重も個別に確認。ドラッグ、スクロール、トラックパッドのイベント生成と模擬した権限喪失時の切断も確認。API 37にマウス相当のイベントを注入し、Macのテストアプリでクリックとスクロールを受信。テストアプリのコンテキストメニューとモーダルダイアログがMac側の映像に含まれ、API 37から操作できることを確認。画面全体に切り替えてメニューバーの項目を選択する操作も確認 | アプリがサイズ変更や復元を拒否する場合がある。手動リサイズ時にScreenCaptureKitの中断通知で接続を終了する場合がある。フォーカス変更はOSが拒否する場合がある。アプリ外に生成されるメニュー・ダイアログ、一般アプリ、実際のマウス・トラックパッド、権限取り消しと操作感は未検証 |

| クリップボード | 認証済み接続でAndroidの共有ボタンと自動同期を操作し、AndroidエミュレーターのクリップボードとMacの隔離ペーストボード間で双方向の日本語・絵文字を転送 | Macの通常のペーストボード、Android実機、ロック時とすべての競合は未検証 |

## 重要な制約

- 画面ロックを確実に検出できること、ロック中に入力を拒否できることは未検証です。フォーカス・権限の確認とイベント発行の間にも競合が残ります。
- Mac側で手動でウインドウをサイズ変更した場合、Macが使う最新の座標情報とAndroidに表示中の映像が異なる可能性があります。自動リサイズでは映像を停止してから変更しますが、手動変更中の映像と操作の同期は未解決です。
- 実ネットワークやVPNを使った接続と、接続先の公開範囲は未検証です。
- 実画面の相互接続検証では1280×800がVideoToolboxの`kVTParameterErr`（-12902）となり、1152×720は受信できました。両端のWebRTCが提示したH.264 Level 3.1を指定したMacのハードウェアエンコーダー単体でも1280×800と1920×1080は同じエラーとなり、720×1280は合成フレームをエンコードできました。Level 4.0では1920×1080の合成フレームをエンコードできましたが、アプリ間交渉とAndroidでの受信は未検証です。製品の暫定上限は長辺1280・短辺720で、縦長画面の相互接続は未検証です。
- 音声転送は未実装です。macOS向けWebRTCにはカスタム音声デバイスのヘッダーが含まれません。同じ配布物のMac Catalyst向けヘッダーを一時的に参照したMac間の検証では、合成音声の送受信を確認しました。製品への取り込み方、ScreenCaptureKitとの接続、Androidでの受信は未検証です。
- リモート操作の遅延、画質、長時間安定性、消費電力と各OS・CPU・端末の組み合わせは実機で未検証です。
