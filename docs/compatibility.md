# 互換性

以下は対応候補です。ビルドやエミュレーターでの確認と実機での動作は区別します。実機検証を含む完了条件は[テスト計画](testing.md)を参照してください。

| 対象 | 候補・確認状況 |
|---|---|
| macOS | macOS 13以降。最低OSを13としたビルドは成功したが、macOS 13での実行は未検証 |
| Mac CPU | Apple Silicon・Intel。両方を含む開発用アプリとWebRTCフレームワークをビルド済み。Intel実機は未検証 |
| Android | Android 8 / API 26以降。API 26・36・37のarm64エミュレーターでテスト済み。API 37.2・16 KBページでもアプリと認証・通信のテストを実施。実機は未検証 |
| Android ABI | APKにarm64-v8a・armeabi-v7a・x86・x86_64のWebRTCライブラリを同梱。arm64とx86_64のエミュレーター以外は未検証 |
| 接続 | 到達可能なLAN・VPNなど。別端末間のLAN接続、VPN、モバイル回線と接続先の公開範囲は未検証 |
| 配布 | ローカル確認用Macアプリと未署名Android APKをビルド済み。配布用署名・公証・実機への配布は未検証 |

## 主な検証結果

2026-11-28時点。MacはmacOS 26.7.3・Apple Silicon・Xcode 27.2、Androidは同じMac上のエミュレーターです。画面取得・操作の結合検証は主に旧WebRTC 158.0.0で実施しました。LiveKitWebRTC 150.7871.08への変更後は、Macの画面取得・操作を含む自動テストとAPI 26・37の製品WebRTC処理間で合成映像・音声、クリックイベント、テスト用ウインドウの映像を確認しています。API 37ではMac内の中継を使い、ペアリング・認証後にAndroidアプリの選択画面からウインドウ映像を表示しました。Android側は1.3.10を使用しました。自動テストは[開発ガイド](development.md)を参照してください。

## 重要な制約

- 画面ロックを確実に検出できること、ロック中に入力を拒否できることは未検証です。フォーカス・権限の確認とイベント発行の間にも競合が残ります。
- ウインドウの手動リサイズを検知すると入力を止めて接続を終了します。検知前にサイズが戻った場合や、確認から入力の間に変わった場合の競合は残ります。アプリやOSがフォーカス・リサイズ・復元を拒否する場合もあります。
- 標準解像度はAndroidが提示するH.264 Level 3.1の画素数に収めます。旧WebRTCでは1280×800と1920×1080のエンコードが失敗しました。新しいWebRTCでは制限を通さない1920×1080の合成映像をAPI 26・37で受信しましたが、どちらもソフトウェアデコーダーでした。実機では未検証です。詳細は[ADR 0013](decisions/0013-capture-resolution.md)を参照してください。
- リモート操作の遅延、画質、長時間安定性、消費電力と各OS・CPU・端末の組み合わせは実機で未検証です。
