# 互換性

以下は対応候補です。ビルドやエミュレーターで確認したことと、実機での動作は区別します。実機検証を含む完了条件は[テスト計画](testing.md)を参照してください。

| 対象 | 候補・確認状況 |
|---|---|
| macOS | macOS 13以降。最低OSを13としたビルドは成功したが、macOS 13での実行は未検証 |
| Mac CPU | Apple Silicon・Intel。両方を含む開発用アプリとWebRTCフレームワークをビルド済み。Intel実機は未検証 |
| Android | Android 8 / API 26以降。API 26・36・37のarm64エミュレーターでテスト済み。実機は未検証 |
| Android ABI | APKにarm64-v8a・armeabi-v7a・x86・x86_64のWebRTCライブラリを同梱。arm64とx86_64のエミュレーター以外は未検証 |
| 接続 | 到達可能なLAN・VPNなど。別端末間のLAN接続、VPNとモバイル回線は未検証 |
| 配布 | ローカル確認用Macアプリと未署名Android APKをビルド済み。配布用署名・公証・実機への配布は未検証 |

## 主な検証結果

2026-11-27時点。特記しない限り、MacはmacOS 26.7.3・Apple Silicon・Xcode 27.2、Androidは同じMac上のエミュレーターです。WebRTCはmacOS側158.0.0、Android側1.3.10を使用しました。自動テストは[開発ガイド](development.md)の手順で実行できます。両OS間の一時テストは検証専用の保存領域を使い、テストコードは残していません。

| 対象 | 確認した範囲 | 未検証・制約 |
|---|---|---|
| ペアリング・認証 | AndroidのAPI 26・36・37エミュレーターとMacを接続。手動または仮想カメラのQRによる登録、再認証、不一致の証明書の拒否を確認 | 実カメラ、別端末、実機の鍵保護とVPNは未検証 |
| 映像 | Mac実画面の受信、画面の回転・接続終了とウインドウ選択を確認。経路制限の削除後はMac・Android間の合成映像の受信を確認 | 削除後の認証から実画面までの通し動作、実際の見た目、一般アプリのウインドウ、最小化、複数画面、Android実機は未検証 |
| 文字・キー入力 | 日本語IMEの変換確定後、PID指定で別プロセスのテスト用Macアプリの文字欄へ入力。長い文字列の分割、発行確認と未確認時の案内、Androidでフォーカス移動後の古いIME接続の拒否もテスト | Macのフォーカス判定と配送先を差し替えた。通常のグローバル配送、一般アプリ、他のIME、物理キーボードと実機は未検証 |
| ポインター・ウインドウ | 認証済み接続でクリック、ドラッグ、スクロール、トラックパッドのイベント生成を確認。対象ウインドウの変更時と、模擬したAccessibility権限喪失時の切断を確認 | イベント送信先を差し替えた。OSへの実配送、実際の権限取り消しと操作感は未検証 |
| 接続終了 | Android 15 x86_64とAndroid 17 arm64エミュレーターの2ピアで、制御チャネルの閉鎖、ローカルとの同時終了、未確認文字列の検知を確認 | 両OS間での同時終了とAndroid実機は未検証 |
| クリップボード | Macの隔離ペーストボードとAndroidテストコード間で手動共有と自動同期の要求・応答を確認 | 通常の両OSクリップボード、画面操作、実機、ロック時とすべての競合は未検証 |

## 重要な制約

- 画面ロックを確実に検出できること、ロック中に入力を拒否できることは未検証です。フォーカス・権限の確認とイベント発行の間にも競合が残ります。
- 実ネットワークやVPNを使った接続と、接続先の公開範囲は未検証です。
- 実画面の相互接続検証では1280×800がVideoToolboxの`kVTParameterErr`（-12902）となり、1152×720は受信できました。両端のWebRTCが提示したH.264 Level 3.1を指定したMacのハードウェアエンコーダー単体でも1280×800と1920×1080は同じエラーとなり、720×1280は合成フレームをエンコードできました。Level 4.0では1920×1080の合成フレームをエンコードできましたが、アプリ間交渉とAndroidでの受信は未検証です。製品の暫定上限は長辺1280・短辺720で、縦長画面の相互接続は未検証です。
- 音声転送は未実装です。macOS向けWebRTC配布物でカスタム音声デバイスの公開ヘッダーを確認できず、ScreenCaptureKitの音声を製品のWebRTC音声ソースへ取り込む方法は未確定です。
- リモート操作の遅延、画質、長時間安定性、消費電力と各OS・CPU・端末の組み合わせは実機で未検証です。
