# ADR 0013: 映像の最大解像度

- 状態: 採用
- 日付: 2026-11-27

## 背景と決定

接続環境や端末によって映像の負荷を抑えられるよう、Mac側で最大画素数を標準（約92万画素）または低解像度（約41万画素）から選ぶ。設定は保存し、次に画面またはウインドウの共有を開始するときに適用する。

既定のWebRTCが提示するH.264 Level 3.1では1フレームあたり3,600マクロブロックが上限である。標準はこの上限、低解像度は1,620マクロブロックを使い、縦横比を保ちながら収まる偶数サイズに縮小する。16×16単位の端数とLevel 3.1の一辺の上限も考慮し、元の映像は拡大しない。16:9なら標準は1280×720、低解像度は約854×480となる。フレームレート、ビットレートや通信状況に応じた自動調整は変更しない。[WebRTCのLevel定義](https://webrtc.googlesource.com/src/+/refs/heads/main/api/video_codecs/h264_profile_level_id.cc)

## 検証と制約

サイズの計算、設定保存と不正設定からの既定値への復帰をテストした。API 26・37エミュレーターで1280×800のテスト用ウインドウから1206×752の映像を受信し、API 26では800×1000の縦長映像と低解像度の800×500も受信した。別OS・Intel・実機、文字の視認性、転送量や遅延は未検証。上限は一定の品質や通信量を保証するものではない。
