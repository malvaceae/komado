# ADR 0009: ウインドウ単位の操作

- 状態: 採用
- 日付: 2026-11-27

## 背景

ウインドウ単位の映像は他のウインドウに隠れていても取得できるが、通常のマウスイベントはその時点の画面座標に配送される。映像の座標だけで送信すると、手前の別ウインドウを誤操作する可能性がある。

## 選択肢と検証結果

バックグラウンドのアプリへイベントを直接送る方式は、アプリごとの振る舞いや公開APIの制約がある。初期実装では通常の入力イベントを使い、Accessibilityの位置判定とWindow ServerのウインドウID・所有プロセス・位置・サイズを操作時に照合する。画面全体を覆うDockの管理用ウインドウがあるため、単純な矩形の前後順だけでは実際の入力先を判定できない。キーボードはフォアグラウンドのフォーカスウインドウのプロセスと位置・サイズも照合し、同じプロセスに同じ位置・サイズのウインドウが複数ある場合は拒否する。

自プロセスの一時ウインドウでScreenCaptureKitとWindow Serverが返す位置・サイズの一致を確認し、別の一時GUIアプリでフォーカスとウインドウ・ボタンへの入力先の照合、クリックイベント生成および他のウインドウに覆われた場合の拒否を確認した。クリックの送信先を差し替えた検証に加え、認証済み接続から別プロセスのテストアプリへ通常のグローバル配送を確認した。一般のアプリやAndroid実機は未検証である。

## 決定と理由

認証済みのウインドウ一覧から選んだ対象に限り、Mac側の操作許可とAccessibility権限を必要とする。操作開始時に対象を一意に識別できれば、Accessibilityのウインドウ前面化とアプリのアクティブ化を要求する。アクティブ化はOSやアプリにより保証されないため、実際の入力時の照合は維持する。画面上にあるウインドウを対象とし、操作時に同じIDとプロセスの現在の位置を使う。ドラッグ中の座標変換には押し始めの位置を使い、移動量が累積しないようにする。入力先は引き続き現在のウインドウと照合する。対象がなくなった場合や、操作時にサイズ変更を検知した場合は接続を終了する。ポインター操作はAccessibilityの位置判定が対象と一致しない場合に拒否する。押下中に判定できなくなった場合は操作を終了し、押下を解除する。


## 影響・制約・未解決事項

- 他のウインドウに隠れた部分や最小化されたウインドウは操作できない。移動後は操作時に取得した位置を使う。リサイズ時の扱いと残る競合は[ADR 0016](0016-window-resize.md)を参照する。
- ウインドウの切り替えや位置の変更と入力イベント配送の間には競合があり、完全な排他は保証できない。
- ウインドウ情報の照合を入力時に行うため、性能や半透明・特殊形状のウインドウ、Accessibilityで表現されないオーバーレイに対する挙動の確認が必要である。判定できない場合は操作を拒否する。
- アプリ単位の操作は[ADR 0017](0017-application-capture.md)を参照。ウインドウ外のメニュー操作、実機、別アプリ、Tailscaleや実際の操作感は未検証。
