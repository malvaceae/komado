# ADR 0009: ウインドウ単位の操作

- 状態: 採用
- 日付: 2026-11-27

## 背景

ウインドウ単位の映像は他のウインドウに隠れていても取得できるが、通常のマウスイベントはその時点の画面座標に配送される。映像の座標だけで送信すると、手前の別ウインドウを誤操作する可能性がある。

## 選択肢と検証結果

バックグラウンドのアプリへイベントを直接送る方式は、アプリごとの振る舞いや公開APIの制約がある。初期実装では通常の入力イベントを使い、Accessibilityの位置判定とWindow ServerのウインドウID・所有プロセス・位置・サイズを操作時に照合する。画面全体を覆うDockの管理用ウインドウがあるため、単純な矩形の前後順だけでは実際の入力先を判定できない。キーボードはフォアグラウンドのフォーカスウインドウのプロセスと位置・サイズも照合し、同じプロセスに同じ位置・サイズのウインドウが複数ある場合は拒否する。

自プロセスの一時ウインドウでScreenCaptureKitとWindow Serverが返す位置・サイズの一致を確認し、別の一時GUIアプリでフォーカスとウインドウ・ボタンへの入力先の照合、クリックイベント生成および他のウインドウに覆われた場合の拒否を確認した。クリックの送信先はテスト用に差し替えた。PID指定配送の試行では対象が受信せず、製品のグローバル配送、一般のアプリやAndroid実機は未検証である。

## 決定と理由

認証済みのウインドウ一覧から選んだ対象に限り、Mac側の操作許可とAccessibility権限を必要とする。画面上にあるウインドウを対象とし、操作時に同じIDとプロセスの現在の位置・サイズを使う。対象がなくなった場合は接続を終了する。ポインター操作はAccessibilityの位置判定が対象と一致しない場合に拒否する。押下中に判定できなくなった場合は操作を終了し、押下を解除する。



## 影響・制約・未解決事項

- 他のウインドウに隠れた部分や最小化されたウインドウは操作できない。移動・リサイズには操作時に取得した位置・サイズを使う。Androidに表示中の映像とMac側の最新情報には時間差があり得る。
- ウインドウの切り替えや位置の変更と入力イベント配送の間には競合があり、完全な排他は保証できない。
- ウインドウ情報の照合を入力時に行うため、性能や半透明・特殊形状のウインドウ、Accessibilityで表現されないオーバーレイに対する挙動の確認が必要である。判定できない場合は操作を拒否する。
- フォーカスの自動変更、アプリ単位の操作やウインドウ外のメニュー操作は未実装。実機、別アプリ、Tailscaleや実際の操作感は未検証。
