# ADR 0006: ウインドウの選択

- 状態: 採用
- 日付: 2026-11-27

## 背景

AndroidからMacの単一ウインドウを選び、画面全体を共有せずに表示する。ウインドウ名は個人情報を含み得るため、認証と取り扱いを明確にする。

## 選択肢と検証結果

ScreenCaptureKitの[共有可能な対象一覧](https://developer.apple.com/documentation/screencapturekit/scshareablecontent)から、デスクトップを除き非表示の対象も含めて取得する。検証環境では所有アプリと有効なサイズのある候補が143件あり、少数件で打ち切る方式では対象を見つけられない可能性がある。[コンテンツフィルター](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)の単一ウインドウ指定を使い、自プロセスのテストウインドウの映像を取得できた。

## 決定と理由

認証済みTLS上で一覧を最大32件ずつ返し、オフセットの表現範囲に合わせて最大65,535件とする。上限を超える場合は候補を黙って省略せず失敗させる。ScreenCaptureKitの画面上の状態を取得時点の情報として表示し、最小化などの理由は推測しない。選択画面から一覧を手動で再取得でき、古い候補は破棄する。自動の変更通知は未実装。選択対象は同じ接続で送信済みの候補に限定し、ウインドウIDと所有プロセスIDを開始要求時とキャプチャ開始時に照合する。タイトルやサイズは変化し得るため同一性の条件にしない。名称はログや永続ストレージに記録しない。

## 影響・制約・未解決事項

OSが閉じたウインドウの情報を保持する場合や、同じプロセス内でウインドウIDが再利用される競合は、この照合だけでは完全には防げない。単一ウインドウのキャプチャには別ウインドウのメニューやダイアログが含まれない場合がある。テスト用ウインドウは最小化中も一覧に残るが、キャプチャは停止し、復元後も再開しなかった。操作対象の選択時に最小化・復元・終了を要求でき、復元後に再度選択して映像を開始する。一般アプリ、非表示、Android実機、Intel MacやVPN経由の動作は未検証。
