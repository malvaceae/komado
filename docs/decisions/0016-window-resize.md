# ADR 0016: ウインドウの自動リサイズ

- 状態: 採用
- 日付: 2026-11-28

## 背景

Androidで操作するウインドウの縦横比を表示領域に合わせる。映像と操作座標が切り替え途中で食い違わないようにする。

## 選択肢と検証結果

映像の転送中にリサイズする方法では、古い映像と新しい座標の対応が保証できない。API 37エミュレーターで古い映像を保持したままウインドウを拡大し、意図した位置と異なる場所へのクリックを再現した。映像を停止してからAccessibilityでサイズを変更し、再取得する方法を、別プロセスのテストウインドウで確認した。最小サイズ、回転・全画面切り替え、解除・切断時の復元も確認した。

## 決定と理由

Androidで明示的に自動調整を有効にした場合、映像表示領域の縦横比に近づける。Macでは対象をウインドウID・プロセス・Accessibilityの位置とサイズで一意に照合し、サイズ変更が許可される場合だけ実行する。現在の面積を目安とし、対象ディスプレイの使用可能なサイズに収める。Androidの向きや全画面表示が変わると映像を停止して調整し直す。解除、対象変更、切断時には保存した位置とサイズへの復元を試みる。

手動リサイズで操作中のウインドウのサイズが変わった場合、次のポインター・キー入力を実行せず接続を終了する。Androidは再接続を試み、Macで操作を再許可すると新しい映像と座標で操作を再開できる。API 37で古い映像に対するクリックの拒否と、再接続・再許可後の入力を確認した。

## 影響・制約・未解決事項

アプリの最小サイズ、固定サイズ、権限やウインドウの終了により変更・復元できない場合がある。一般アプリ、実機と複数ディスプレイは未検証。入力の確認前にサイズが元に戻った場合や、確認からOSへの入力の間に変わった場合の競合は残る。
