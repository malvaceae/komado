# ADR 0011: 手動クリップボード共有

- 状態: 採用
- 日付: 2026-11-27

## 背景

テキストをMacとAndroidの間で共有する。一方の端末のクリップボードには、もう一方へ送る意図のない情報が含まれる場合がある。Androidのバックグラウンドアクセス制限にも対応する必要がある。

## 選択肢と検証結果

接続時の無条件な同期は、操作していない内容も転送するため採用しない。初期実装は各転送をAndroidで明示的に指示し、Macでもセッションごとに共有を許可する。テキストのみ、最大16,384 UTF-8バイトを扱い、URIや複数項目、不正な文字列を拒否する。

共有形式と許可・期限切れ・取り消し時の動作は両OSのテストで検証した。Macの隔離ペーストボードとAndroid 8・17エミュレーターをそれぞれ実際に接続し、テスト用テキストの両方向の要求・応答を確認した。Androidの実クリップボードと操作画面、一般のアプリやAndroid実機での操作は未検証である。

## 決定と理由

- 端末認証、操作許可と別に、Macの「クリップボード共有を許可」を必要とする。操作許可の解除や操作セッション終了で共有許可も解除する。
- AndroidからMacへ送る際、まず本文を含まない準備要求を送り、Macの許可を確認してからAndroidのクリップボードを読み取り、本文を送る。許可は一度の送信に限り、10秒で失効する。
- MacからAndroidへ取得する際は明示要求に応じて読み取る。応答を受け取るまでにAndroidの内容が変更された場合や、アプリがフォーカスを失った場合は上書きしない。
- 実装済みの暗号化されたReliable / Ordered制御チャネルを使い、機能一覧で対応を確認する。認証済みセッション、キャプチャリビジョン、連番を確認し、ドラッグ中や短時間の連続要求は受け付けない。
- Androidが受け取った内容は機密表示のヒントを付ける。内容、入力文字列、認証情報をログやアプリの永続ストレージに保存しない。

## 影響・制約・未解決事項

- 画像やファイル、16,384バイトを超えるテキストは未対応。自動同期は[ADR 0012](0012-automatic-clipboard.md)で別途扱う。
- クリップボード変更通知・許可取り消し・入力の配送は非同期であり、全ての競合を排除できるわけではない。実際のロック状態、Android実機、Tailscaleや多様なアプリでの動作は未検証。
- AndroidのOSやキーボードによる通知・表示、受け取ったデータの保存先での扱いは各環境に依存する。
