# ADR 0015: 確定文字列のイベント発行確認

- 状態: 採用
- 日付: 2026-11-27

## 背景

確定文字列は信頼済みの制御チャネルで送るが、Macがフォーカスや権限を確認できない場合は入力を拒否する。従来の形式には発行結果がなく、Androidは拒否を検知できなかった。長文は複数メッセージに分割されるため、部分的な入力にも気付きにくい。

## 決定と理由

Macが`keyboard.text-ack`を通知した場合、Androidは確認を要求する`keyboard.text.checked`を送る。Macは安全条件と連番を確認して押下・解放イベントを発行できた場合に限り、同じ連番の`keyboard.text.posted`を返す。確認を必要とする入力を拒否した場合や確認を送れない場合は接続を終了する。Androidは未確認の連番を順番に管理し、異なる確認やタイムアウト、確認前の切断では接続を終了し、部分的に反映された可能性を表示する。

旧Macに機能がない場合は従来の`keyboard.text`を使う。旧Androidからの従来形式には確認を返さない。これにより既存のクライアントが未知の応答を受け取らない。

## 影響・制約・未解決事項

- 確認はCore Graphicsイベントの発行までであり、対象アプリが文字を受け取ったことや処理したことは保証しない。
- 複数の断片の発行は原子的ではない。切断時にはすでに発行した部分を取り消せない。
- 確認の待機には上限があり、遅延や切断時には実際に入力済みであっても結果を確認できない。
- 旧Macでは従来どおり受理を確認できない。実際のアプリやAndroid実機での挙動は別途検証する。
