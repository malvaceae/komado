# セキュリティ

[開発計画書 §9](development-plan.md#9-セキュリティ)を要件の原案とし、ここでは現在の信頼境界と制約をまとめます。通信形式は[通信プロトコル](protocol.md)、検証範囲は[互換性](compatibility.md)を参照してください。

## 認証と通信

ネットワークへの接続やIPアドレスを端末認証の代わりにしません。シグナリングにはTLS、映像・音声と操作にはWebRTCのDTLS / SRTPを使います。独自の暗号化は実装しません。

MacはKeychainのP-256秘密鍵を使った自己署名証明書を持ち、SHA-256フィンガープリントを表示します。Androidは信頼できるMacの画面に表示されたQRコードの値を使って証明書、有効期間、自己署名と用途を検証し、TLS確立後にペアリング情報を送ります。鍵や証明書が欠損した場合は自動で別のidentityを作りません。証明書の更新・欠損時の復旧手順は未実装です。

Macが発行するペアリング情報は32バイトの乱数で、有効期間120秒、失敗5回または使用後に無効化します。Android Keystoreの端末鍵でチャレンジに署名し、検証後に公開鍵をMacのKeychainへ登録します。再認証時も登録済みの公開鍵で署名を検証し、登録を再確認します。チャレンジは30秒で失効し、一度だけ消費します。切断や招待の再発行で保留中の処理を無効化します。

QR画像、一時コード、入力内容、画面内容、クリップボード内容、認証情報、ウインドウ名やアプリ名をログに記録しません。ペアリングコード欄は自動入力とビュー状態の保存を無効にし、IMEに個人向け学習を行わないよう要求しますが、IMEによる遵守は保証できません。

Macは利用可能な各インターフェースのアドレスで待ち受けます。通常のインターフェースではローカルリンクに制限し、トンネルでは接続範囲をトンネルの設定に委ねます。同時接続は全経路で1件、認証期限は30秒、接続試行は10回／60秒です。別端末からの到達範囲とWebRTCの動的UDPポートを含む公開範囲は未検証です。

Android 17以降は同一LANのTCP・UDP通信に必要なローカルネットワーク権限を接続時に要求します。拒否された場合もVPN経由の接続は試せます。この権限は認証の代わりにはなりません。[Androidの説明](https://developer.android.com/privacy-and-security/local-network-permission)

Macから端末を切断または待ち受けを停止すると自動再開を拒否します。再接続後の操作とクリップボード共有には再許可が必要です。Macから端末登録を削除する場合は現在の接続を切り、保留中の認証も無効化します。Android側での登録削除はAndroid内の情報と鍵だけを削除します。

## シグナリングとWebRTCの結び付き

ホストを確認したTLS接続でAndroid端末を認証し、同じ接続上でSDPのOfferとAnswerを交換します。SDP内のDTLSフィンガープリントを使ってWebRTCの相手を照合し、接続が確立してから映像と操作を有効にします。SDPの接続候補は書き換えません。[WebRTCのセキュリティアーキテクチャ](https://www.rfc-editor.org/rfc/rfc8827.html)

Androidエミュレーター内の2ピアではOfferのDTLSフィンガープリント改変による接続失敗を確認しました。Mac・Android間や実ネットワークでの改変試験は未実施です。

## 操作と共有

ディスプレイ、アプリ、ウインドウの一覧は認証済み端末にだけ送ります。選択や操作には、同じ接続で送信済みの候補を使います。ウインドウは開始要求時とキャプチャ開始時にウインドウIDと所有プロセスIDを照合します。タイトルやサイズの変更は同一性の条件にしません。OSが閉じたウインドウの情報を保持する場合やIDの再利用、照合後の変更には競合が残ります。

Macの明示的な操作許可とAccessibility権限を操作の開始・実行時に確認します。対象の位置・サイズ、入力先やフォーカスを確認できない場合は操作しません。画面単位のキー入力では、フォーカスされたウインドウの中心が共有画面内にあることを確認します。アプリ単位のポインター操作では入力先のプロセスを照合します。アプリの起動はMac側で保持した候補のパスを使い、端末から任意のパスを受け付けません。

入力は連番とキャプチャリビジョンを検証し、映像の実コンテンツ領域に座標を変換します。ウインドウのサイズ変更を検知した場合は入力せず接続を終了します。ドラッグの終了・切断時はボタンの解放を試みますが、プロセスの異常終了や権限取り消し後の配送は保証できません。対象・許可・フォーカスの確認からOSへの要求までの競合も残ります。

確定文字列はUnicodeキーイベントとして送ります。送信確認はOSイベントの発行を示し、対象アプリへの配送や処理までは保証しません。対象アプリがUnicode文字列を使わない場合もあります。[AppleのAPI説明](https://developer.apple.com/documentation/coregraphics/cgevent/keyboardsetunicodestring%28stringlength%3Aunicodestring%3A%29)、[ADR 0015](decisions/0015-text-posting-confirmation.md)

ユーザーセッションの切り替え、スリープ・ログアウト要求、ディスプレイのスリープや構成変更、AppKitの保護データが利用不可になる通知では転送を停止します。ScreenCaptureKitが空白・中断・停止を通知した場合やフレーム状態を取得できない場合も停止します。これらの通知、保護データの状態、コンソール上のセッションは、画面がロックされていない証拠にはなりません。**画面ロックを確実に検出し、ロック中の入力を拒否できることは未検証です。**

クリップボード共有はMac側で別途許可が必要です。手動転送はAndroidでの明示操作に限り、送信前に一度限り・10秒で失効する許可を確認します。自動同期は両端で有効にした場合のみ行い、Androidがフォーカスを失うと停止します。機密情報の印がない内容は自動転送され得ます。転送はテキストに限り、変更通知と読み書きの間の競合は完全には排除できません。[ADR 0011](decisions/0011-manual-clipboard.md)、[ADR 0012](decisions/0012-automatic-clipboard.md)

音声の共有はMac側で別途許可が必要で、初期状態ではオフです。許可を取り消すと送信を止め、切断時にも解除します。MacのマイクとAndroidの録音は使いません。画面・アプリ・ウインドウごとの音声取得範囲は環境によるため、検証済みの範囲は[互換性](compatibility.md)に記載します。

## 残る検証

- 実機での鍵の保護、QRコード、証明書の更新・失効・復旧。
- 別端末やVPNからの到達範囲、ネットワーク変更、Mac・Android間でのDTLSフィンガープリント改変。
- 画面ロック、スリープ、ディスプレイ変更や権限取り消し時の動作と、フォーカス・入力先変更との競合。
- 一般アプリでの入力とウインドウ操作、実際のクリップボード、複数ディスプレイでの動作。

これらの検証結果を[互換性](compatibility.md)に集約します。通常の接続に成功したことだけで、すべての攻撃や競合への安全性を保証しません。
